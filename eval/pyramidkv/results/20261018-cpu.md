# PyramidKV CPU 성능 측정 — 2026-10-17~18

범위 변경(2026-10-18): 사용자의 요청으로 LongBench 전체 실행은 Linux 예측 184개를
보존하고 중단했다. 이후 21개 태스크의 고정 첫 샘플 1개씩, 양 OS·양 조건 총 84개
예측의 부분 평가로 전환한다. 아래 72회 성능 실측과 JSON의 원본 수치는 변경하지 않았다.
최종 상태(2026-10-19): 선택된 84개 예측이 모두 완료됐고,
[LongBench 부분 평가 결과](20261019-longbench-subset.md)에 태스크별 점수를 기록했다.
성능 JSON에 남은 LongBench 진행 metadata는 성능 보고서 최초 저장 시점의 기록이다.

독립 main baseline `7d14d001`과 PyramidKV 구현 `2013bc91`을 비교했다.
평가 도구는 `38243fdf`이며, 아래 숫자는 합성 없이 실측한 값이다.
Linux와 Windows 각각 36개 본 측정(총 72개), 기능 확인 4개는 통계에서 제외했다.
모든 본 측정에서 실제 decode 128회를 수행했으며 누락·중복·invalid trial은 없다.

Qwen3-0.6B, FP32 weights/activations, FP16-bit UINT16 KV, batch 1,
capacity 4225, NNTR/OMP 4 threads, OpenBLAS 1 thread.
입력은 token ID 5555를 정확히 512/2048/4096개 반복한 성능 부하용 prompt다.
모델의 기존 sampling/EOS 설정을 유지했다. Latency는 로딩을 제외한 CLI `total:`이다.
PyramidKV는 budget 256/window 64/kernel 5/beta 20이며, 공식 integer schedule에 따라
28개 층의 초기 유지 길이는 439~88(평균 263.5)이다.

동일 i7-1165G7 PC에서 빌드와 측정을 겹치지 않고 Linux→Windows 순서로 실행했다.
플랫폼 내부에서 두 조건의 컴파일러·옵션·backend·모델·thread 설정을 맞췄다.
Linux는 WSL2 Ubuntu/GCC 13.3.0, affinity 0,2,4,6이고,
Windows는 native Windows 11 build 26200/MinGW GCC 13.2.0, affinity 미고정이다.
두 플랫폼 모두 release, CPU/OpenBLAS 0.3.26 빌드다.

### Windows native

Baseline 3회·PyramidKV 3회 평균; latency와 memory는 별도 프로세스.

| 입력 tokens | Baseline latency (s) | PyramidKV latency (s) | Latency 변화 | Baseline peak memory (MiB) | PyramidKV peak memory (MiB) | Memory 변화 |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 512 | 44.867 | 40.761 | -9.2% | 2,918.8 | 2,887.8 | -1.1% |
| 2048 | 114.432 | 96.818 | -15.4% | 2,955.8 | 2,956.5 | +0.0% |
| 4096 | 257.935 | 225.726 | -12.5% | 3,082.3 | 3,085.6 | +0.1% |

입력별 평균에 같은 가중치를 준 전체 변화: latency -12.9%, peak memory -0.3%.

메모리: PSAPI current Working Set, 50 ms 표본 최대. OS peak와 구분합니다.


메모리는 모델 로딩과 prefill을 포함한 프로세스 생애의 **표본 최대**다.
Linux는 원본 `Applications/utils/mem_usage.sh`의 smaps RSS(1초 sleep + loop 비용),
Windows는 PSAPI current Working Set(50 ms sleep + observer 비용)을 사용했다.
기존 helper의 `sample_interval_seconds=0.05` 인자는 Windows에만 적용된다.
OS peak는 별도 필드에 보존했으며, 표본 최대와 혼용하지 않았다.

층별 prompt KV를 압축하고 decode 토큰을 추가하지만 원래 KV allocation은 유지한다.
따라서 표의 resident-memory 변화는 KV allocation 해제량이 아니다.
관측된 전체 peak memory 변화는 작으며, 표준편차와 개별 값은
[측정 JSON](20261018-cpu.json)에 보존했다. 반복은 조건·입력·phase별 실제 3회다.
GQA mean 집계와 선택 위치의 시간순 정렬 등 공식 구현과의 포팅 차이는
[구현 설명](../README.md)에 명시했다.

Windows는 baseline과 동일한 task-local MinGW 호환 설정 및 main-return adapter를 사용했다.
모델/지역 객체 정리 후 종료하고, 기존 DLL 전역 destructor 교착 구간은 제외한다.
PyramidKV의 CausalLM 객체와 실행 파일은 새로 빌드했다. 변경 없는 core DLL/import는
main 소스·컴파일러·176개 core 컴파일 metadata block의 동일성을 확인한 뒤 재사용했다.
전체 빌드 매트릭스 CI 통과를 주장하지 않는다.

Linux 모델 테스트는 88 passed + 기존 ARM 전용 1 skipped, KV cache 테스트는 20 passed였다.
두 OS에서 tiny-model off/zero/uncompressed/compressed 동작을 확인했고,
Windows의 실제 Qwen3 UTF-8 입력도 확인했다. 변경 C++은 clang-format 14 검사를 통과했다.

LongBench v1은 사용자가 범위를 줄여 **21개 태스크 × 고정 첫 샘플 1개**로 완료했다.
양 OS·양 조건 총 84개 예측이며, 태스크당 n=1인 진단용 부분 평가다.
공식 prompt/scorer와 데이터 revision을 고정했고 입력 상한은 8,192 tokens다.
[완료 보고서](20261019-longbench-subset.md)에 품질 결과와 복구 기록을 정리했다.
중단한 전체 평가의 Linux 예측 184개와 원본 로그는 보존했다.

전체 stdout/stderr, memory 표본, 원본 config/JSON/CSV, 소스·실행 파일·runtime hash와
검증 로그는 로컬 `build/validation/pyramidkv-run/`에 보존했다.
`performance-{linux,windows}/`는 완료된 성능 실험,
`longbench-subset-{linux,windows}-v2/`는 완료된 품질 부분 평가다.
`subset-pipeline-status.json`과 각 품질 manifest가 최종 상태의 원본이다. 이 디렉터리는 git에서 제외되며, 측정 JSON에 원본 manifest hash를 기록했다.
