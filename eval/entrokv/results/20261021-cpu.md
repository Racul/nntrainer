# EntroKV versus independent main: CPU measurements

Measured on 2026-10-21, with Qwen3-0.6B FP32 weights and activations,
FP16-bit UINT16 KV, batch 1. This evaluates the opt-in Entro-SnapKV port;
the baseline is a separate build of main, not the method binary with a flag off.
Linux/WSL2 and native Windows are separate comparisons.

At this configuration, overall CLI latency increases **20.4% on Linux** and
decreases **17.9% on native Windows**. On Linux, the larger prefill cost at
2048/4096 tokens outweighs faster generation. On Windows, both stage means
decrease at those input lengths. The enabled attention path differs from main's
path, so these results include that integration cost and are not an allocator-only
comparison.

- Baseline: `7d14d001c9e70014de515dbd00ee6986d50d365f`.
- Measured implementation: `31f92a73cd7c0690158dedb29cbef8d5b7877512`.
- Inputs: 512, 2048, 4096 tokens. Capacity 4225; requested and actual decode
  steps 128 in every function and measured run. The initial prefill output is
  distinct from the CLI's generation-loop count.
- EntroKV: beta 0.3, alpha 1 (instance-only), observation window 32, max-pool
  kernel 7, GQA mean entropy. No calibrated prior or Eq. 10 normalization.
- Each input/condition/phase has three valid fresh-process measurements: 36 per
  platform, 72 overall. One invalid Linux sampler attempt is retained separately
  and excluded from means. Two function runs per platform are also excluded.
  Conditions alternate B/E, E/B, B/E within each phase and input. Linux runs
  complete before Windows starts; builds and inference do not overlap.

The primary latency is CLI `total:` excluding model load. Memory is a separate
process run and a sampled process-lifetime maximum. Negative changes denote
lower time or memory. Means and changes use unrounded values. Each platform's
overall change is the ratio of equal-weight input-length means, not the mean
of the three percentages. The platforms are never pooled.

## Interpretation and limits

The implementation preserves the cache manager's capacity allocation. It
compacts each head's prompt K/V, pads to the largest quota and appends generated
tokens after that span. A process memory change is not evidence of releasing
the KV allocation. Head quota sums, padded spans and allocation sizes are
different quantities; activation logs record quotas and spans.

Enabled EntroKV computes attention in host blocks of at most 32 queries to
collect the observation probabilities without another QK multiplication or a
new full-prompt squared score plane. This replaces main's normal prefill
attention path. The prefill/generation table therefore matters: any lower
decode cost must be weighed against prefill overhead. Results describe this
port and configuration, rather than an allocator-only kernel comparison or
general performance of the paper's implementation. Guaranteed-full-retention
cases and disabled configurations keep the original attention path.

The synthetic input is tokenizer token 5555 (`' weeks'`) repeated to the exact
input length, encoded without special tokens. It is a performance workload,
not a quality test.
Original generation settings are retained: sampling enabled, temperature 0.6,
top-k 20, top-p 0.95, EOS IDs 151645/151643, original default sampling seed 12
(`causallm::kDefaultSamplingSeed`, reseeded for each run).
Every run completed 128 decode iterations; no unequal-EOS work is used to
claim a speedup. No thermal/frequency controls or confidence intervals are
claimed. LongBench was explicitly excluded by the updated execution request;
no quality scores or synthetic augmentation were produced.

## Reproduction and validation

Use [the evaluation helper and configuration instructions](../README.md).
[Measured values and provenance](20261021-cpu.json) include three individual
values, sample SDs, actual decode counts, model and runtime hashes, compiler
versions, build options and activation settings.
[Trial CSV](20261021-trials.csv) includes the four excluded function runs with
`phase=function`. Raw configuration, stdout/stderr, memory samples and failed
premeasurement validation attempts are retained in the local validation archive
at `build/validation/entrokv-run`; original recorded paths are preserved.
The public JSON omits unrelated runtime search paths; the original manifests
remain in that archive.

One Linux EntroKV memory attempt at 4096 tokens was rejected because process
exit raced the sampler's final read, leaving a blank terminal RSS sample.
Inference itself completed 128 decode iterations. The failed manifest and log
are preserved under `measurement-failures/` and `failed_attempts` in JSON; that
attempt is excluded from means. Only that slot was repeated, using the exact
same source, binaries, helper, protocol and sampler. The other 35 valid Linux
measurements were retained. There was no algorithm adjustment based on results.

The host is an Intel Core i7-1165G7 (4 cores/8 logical processors). Linux uses
GCC 13.3 on WSL2, CPU affinity 0,2,4,6; native Windows uses MinGW-W64 GCC 13.2
x86_64-ucrt-posix-seh, without explicit affinity. NNTR and OMP threads are 4;
OpenBLAS threads are 1 on both. OS/runtime versions and library hashes are
recorded in JSON. Linux samples model-PID smaps RSS with the unchanged repository
`mem_usage.sh` at approximately one second; Windows samples current WorkingSetSize
via PSAPI every 50 ms. These metrics and OS-provided peaks are stored separately.

All CausalLM feature objects were built afresh. Unchanged core objects were
reused only after verification of 817 source files, generated headers,
compiler and compile flags: 352 Linux core compile blocks and 176 Windows
blocks. Application flag comparisons covered 75 Linux and 68 Windows blocks,
with no meaningful differences between conditions. The main baseline's 2236
tracked source blobs were checked against its pinned commit. Binary and
dynamic-library checksums identify the actual evaluated code.

The native Windows baseline and method both use the same evaluation-only
MinGW compatibility flags/exports and main-return exit adapter. After original
main returns and model/local cleanup completes, the adapter preserves its exit
code and flushes output while bypassing DLL global shutdown. Thus native
process lifetime excludes that shutdown; timed-out inference is not counted as
success. No repository or vendored source was patched for the adapter.

Linux validation: EntroKV Tensor policy 15 passed; existing cache manager 20
passed; model suite 83 passed and one ARM/NEON-only QINT4 reference case skipped.
Native Windows: the same Tensor policy source compiled and ran with 15 passed.
Both platforms passed actual tiny-CLI checks for absent configuration, beta=0,
guaranteed full retention and compressed activation (prefill 16, decode 8).
Absent/zero/full-retention generated outputs matched exactly. The broader
model suite ran on Linux; it is not claimed as a native Windows suite run.

The source follows [EntroKV, Eq. 8/9 and Appendix E.1](https://proceedings.mlr.press/v306/gao26a.html).
The author's linked code was unavailable during implementation, so author-code
parity is not claimed. Optional merging variants, global budget normalization,
calibration and unsupported session/backend combinations are outside this port.
