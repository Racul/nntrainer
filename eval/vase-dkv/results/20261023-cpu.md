# VaSE-DKV CPU 평가 — Linux / native Windows

평가 계획은 각 OS에서 입력 512/2048/4096별 **baseline 3회·방법론 3회**, latency/memory 별도 프로세스입니다. 실제 완료 범위는 아래에 명시합니다.
본 측정 72/72회 완료입니다.
별도의 실제 모델 기능 확인 4회 및 Tiny CLI 검사는 통계에서 제외했습니다. 게시를 위해 추론·측정을 재개하지 않았습니다.

Qwen3-0.6B, FP32 weights/activations, half-bit KV(UINT16), batch 1, capacity 4225, decode 요청 128.
main baseline `7d14d001c9e70014de515dbd00ee6986d50d365f`; NNTR/OMP 4 threads, OpenBLAS 1 thread.
**현재 포팅은 main과 저장소 예약 정책·decode kernel이 다릅니다. 아래 변화율은 이 차이까지 포함하며 논문 정책만의 이득을 분리한 값이 아닙니다.** 점수 계산·eviction 비용은 추론 시간에 포함했습니다.
Intel i7-1165G7 한 PC에서 ManifoldKV Linux→Windows, VaSE-DKV Linux→Windows, DropKV Linux→Windows 순으로 실행했습니다.
각 방법론·OS의 baseline도 새로 측정했습니다. Linux는 WSL2, Windows는 native PE 실행입니다.
반복 token 성능 입력이며 원래 sampling/EOS를 유지했습니다. **LongBench 및 품질 평가는 제외했습니다.**

- 512 tokens: 실제 레이어별 eviction 횟수 [0].
- 2048 tokens: 실제 레이어별 eviction 횟수 [2].

baseline은 설정·구현의 전체 사전예약 용량이고, 방법론은 prefill 직후 및 마지막 eviction marker의 실제 소유 버퍼 용량입니다.

## 해석 범위

- main은 각 레이어에 max_seq_len 전체를 예약하고, enabled 포팅은 실제 prompt/budget에서 시작해 저장소를 줄입니다. 메모리 변화에는 이 예약 정책 차이와 eviction이 함께 포함됩니다.
- K/V는 실제 작은 Tensor로 교체하고 이전 소유권을 해제합니다. 레이어별 marker와 테스트로 확인했습니다. 다만 로딩·prefill·scratch·old/new slab 동시 존재와 allocator 잔류 페이지 때문에 저장소 축소가 process peak 감소를 보장하지 않습니다.
- x86 main의 기본 flash 설정은 host GEMM decode 경로를 사용하고, compact 포팅은 compute_kcaches/softmax/compute_fp16vcache_transposed의 per-row 경로를 사용합니다. 이 결과는 그 kernel 선택을 포함한 현재 포팅의 결과이며 논문 정책만의 효과를 분리한 비교가 아닙니다. 측정 도중 kernel은 변경하지 않았습니다.
- Linux RSS와 Windows Working Set은 다른 지표입니다. OS 간 수치를 합치지 않습니다. Linux affinity는 0,2,4,6, Windows는 미고정이고 온도·주파수는 제어하지 않았습니다. 작은 변화율의 통계적 유의성을 주장하지 않습니다.
- 방법론별 budget/retention이 달라 동일 budget 순위가 아닙니다. GPU 논문 속도나 품질 재현을 주장하지 않습니다.

설정은 budget=1024, buffer=64, rank=20, seed=42이며 cur_resample_gauss를 사용했습니다. 이번 128-token decode는 논문의 긴 reasoning decode 실험과 다릅니다.

## 검증 및 출처

Linux 모델 테스트 20개와 KVCacheManager 20개, native Windows policy/model/cache 테스트 34개가 통과했습니다.
양 OS에서 작은 모델 disabled/explicit-off/uncompressed/compressed의 16-token prefill·8-token decode를 확인했고, 앞의 세 조건은 동일 출력을 확인했습니다.
모든 본 측정의 실제 token 수, activation/allocation marker, memory 표본·peak·대상 PID, raw 로그 및 실행 중첩을 검증했습니다.
Linux는 GCC 13.3, Windows는 MinGW GCC 13.2 release 빌드입니다. 변경 없는 core만 소스·헤더·컴파일 옵션·toolchain 일치를 검증해 재사용했고 방법론 코드는 새로 빌드했습니다.
Windows는 baseline과 동일한 original-main-return adapter를 사용합니다. 모델·지역 객체 정리와 main 성공 반환 이후 알려진 DLL 전역 종료 hang 구간을 제외합니다. 전체 CI matrix 통과를 뜻하지 않습니다.
순차 검증의 ManifoldKV 준비 단계에서 GTest if/else의 dangling-else 경고를 수정했고, 같은 중괄호 수정을 세 브랜치에 적용했습니다. Windows 공통 테스트 구성의 UNC object 출력·중복 gtest main 문제도 수정했으며 실패 로그는 보존했습니다. 추론 알고리즘은 측정 중 변경하지 않았습니다.
